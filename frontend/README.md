# Forte Vision frontend

React + TypeScript + Vite. Node.js 22.12+.

```sh
npm ci
npm run dev
```

`npm test` — проверка файлов и форматирования времени. `npm run build` — TypeScript и production-сборка.

На главной одна кнопка загрузки, также можно перетащить MOV/MP4 до 200 МБ. После выбора появляется центральный индикатор, затем он перемещается вправо, а слева открывается видеоплеер. На узком экране статус находится под видео. Светлая и тёмная темы переключаются в шапке; выбор сохраняется локально, по умолчанию используется системная тема.

После декодирования первого кадра центральная загрузка сменяется галочкой «Видео загружено». Минимальная длительность загрузки — 0,8 секунды; подтверждение остаётся по центру ещё 1,3 секунды. Затем запускается отдельный индикатор демопроверки ИИ. Сначала текст меняется по центру; через 0,56 секунды начинается сдвиг: он перемещается вправо за 0,94 секунды, и только после завершения этого движения слева плавно появляется видео. Если запись не открылась за 20 секунд или браузер сообщил об ошибке, показывается возможность выбрать другой файл. Демоэтап проверки длится 4,2 секунды. После завершения индикаторов появляется демо-отчёт с двумя заданными исходами и переходом по таймкоду. Отчёт не является анализом загруженного видео: backend и модель пока не подключены.

Тексты этапов плавно смешиваются за 0,44 секунды в общей сетке: старый и новый варианты перекрываются по прозрачности без пустого кадра и изменения высоты блока. Неактивные тексты скрыты от скринридера.

Переходы используют Web Animations API без новых зависимостей: загрузка перемещается в правую панель, видео и заголовок появляются отдельно. Отмена и повторный выбор файла прерывают предыдущие анимации и таймеры. При `prefers-reduced-motion` движение отключается. Тесты также проверяют выполнение действий без анимаций и при быстром повторном нажатии.

Файл открывается через object URL, не отправляется на сервер и не сохраняется после перезагрузки. Для предпросмотра MOV нужен поддерживаемый браузером кодек; альтернатива — MP4/H.264.

Результат заменяет статус в правой панели. Сначала прорисовывается вертикальная карточка, затем её содержимое появляется сверху вниз. Три демоэпизода открывают соответствующие позиции записи; на узком экране карточка остаётся под видео.

## Живой режим (API)

Два режима определяются автоматически при выборе файла:

- **Ключ есть** (`VITE_API_KEY` при сборке или `localStorage["forte-api-key"]`) — файл сразу уходит в
  `POST /api/v1/analyze` локального сервиса (dev-прокси `/api` → `http://127.0.0.1:8000`,
  адрес можно переопределить `VITE_API_BASE`). Ход проверки ждёт реального ответа воркера,
  затем показывается вердикт с реальными кадрами-доказательствами (`src/Verdict.tsx`).
- **Ключа нет или сервис недоступен** — прежний демо-сценарий с двумя исходами, помеченный «ДЕМО».

Запуск связки для проверки:

```sh
cd backend && API_KEY=test-key PIPELINE_DEMO_FACTS=$(pwd)/../fixtures/X-15.json python3 -m uvicorn main:app
cd frontend && VITE_API_KEY=test-key npm run dev   # и выбрать видео
```

Байты демо-вердикта не отправляются на сервер всегда: файл уходит только в живом режиме.
